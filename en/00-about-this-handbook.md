# About This Handbook

This handbook explains how to work with bun.ink: writing, managing versions, working on a text with others. It's written for people who write for a living — not for people who program for a living.

## Who it's for

You don't need any prior knowledge of Git. If you already know what a commit is, you can skip the explanations; if you don't, the handbook will get you there as you work through the chapters in order. Every term is explained exactly once, at the point where you first need it.

What you do need: a browser and a GitHub account. That's it.

## How it's organised

Chapters 01 to 03 get you writing — account, editor, and how projects, folders and documents fit together.

Chapters 04 to 07 are the heart of it: what happens once your texts live in a repository? Connecting a repository, then branches as versions, then commits and history, and finally pull requests for working with your editor. These four build on each other, so read them in order.

From chapter 08 onwards, it's reference rather than reading: AI agents, encrypted areas, statistics and export. These chapters stand on their own.

The full overview is in the repository's table of contents.

## Why the handbook lives in a repository

Because it demonstrates exactly what it describes.

This handbook is written in bun.ink. Every chapter is written in the editor and saved straight into this repository. Drafts live on branches. Revisions come back as pull requests — some from a human, some from an AI agent that reads the repository and proposes changes.

So you can look at the history and trace how this text was worked on: which version came about when, what the editor changed, what was accepted and what wasn't. That's precisely the difference from a text that sits in a document and whose backstory nobody can reconstruct.

## Languages

The writing happens in German. The English version is generated from it and isn't edited by hand. If you spot a mistake in the English version, it's almost always already there in the German text.

## Found a mistake?

Then report it as an issue in this repository, or send a pull request against the German version right away. Both help — including simply pointing out that a passage is hard to follow, even if you don't know how to put it better.

Feature requests for the app itself don't belong here; they go in the public roadmap.
